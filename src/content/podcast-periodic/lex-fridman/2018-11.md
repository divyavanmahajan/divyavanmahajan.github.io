## Overview

November 2018 moved from machine learning theory to the craft of programming. Vladimir Vapnik argued that the hard part of learning is choosing good predicates, while Guido van Rossum and Jeff Atwood talked about building tools and communities for programmers. A common thread was that good design comes from clear constraints rather than raw volume.

## Main themes

### Learning with less data

- Vapnik splits learning into a statistical part, which he considers solved, and an intelligence part: choosing the right predicates and invariants. A good teacher supplies them, so the machine needs far fewer examples ([Vapnik](/podcasts/lex-fridman/2018/11/vladimir-vapnik-statistical-learning/)).
- He uses the duck test to show how a few well-chosen predicates shrink the admissible set of functions, and challenges researchers to match deep learning's MNIST accuracy with a hundred times less data ([Vapnik](/podcasts/lex-fridman/2018/11/vladimir-vapnik-statistical-learning/)).
- Vapnik dismisses deep learning as interpretation rather than mathematics and says AlphaGo shows Go is not very hard. Fridman pushes back on its empirical success ([Vapnik](/podcasts/lex-fridman/2018/11/vladimir-vapnik-statistical-learning/)).

### Designing a language for productivity

- Van Rossum says Python came from one narrow goal, making programmers productive, and borrowed indentation from ABC and literals from C ([Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/)).
- He explains that exploration means more time writing code than running it, so fewer details and a large library speed up iteration ([Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/)).
- Asked about Andrej Karpathy's Software 2.0, he says he would not call training neural networks programming ([Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/)).

### Governing communities

- Van Rossum resigned as BDFL the morning after approving PEP 572, trusting the 50 to 100 core developers to run the language ([Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/)).
- Atwood describes Stack Overflow as a mix of Digg and Reddit voting, Wikipedia-style editing and blog-style ownership, with reputation as the main motivator. It became strict because open-ended questions were not real problems ([Stack Overflow](/podcasts/lex-fridman/2018/11/jeff-atwood-stack-overflow-and-coding-horror/)).
- He argues communities form around an interest graph rather than Facebook's relationship graph and should own their space, which is why Discourse earns money from hosting, not ads ([Stack Overflow](/podcasts/lex-fridman/2018/11/jeff-atwood-stack-overflow-and-coding-horror/)).

### Programming is about people and iteration

- Atwood says effective programmers eventually work mostly in English, and measures a software company by how fast one agreed word change reaches users ([Stack Overflow](/podcasts/lex-fridman/2018/11/jeff-atwood-stack-overflow-and-coding-horror/)).
- Van Rossum notes most developers have given up on bug-free code and rely on retries and timeouts ([Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/)).

## Notable episodes

- [Guido van Rossum: Python](/podcasts/lex-fridman/2018/11/guido-van-rossum-python/): Python's origins, the Python 3 transition and a first-hand account of stepping down as BDFL.
