## Overview

October on The Pragmatic Engineer was about how working engineers actually use AI coding agents, and where the human still has to stay in charge. Armin Ronacher and Addy Osmani gave two practitioner views, one from a small startup and one from inside Google. Between them, a deep dive with Elin Nilsson explained how Google's engineering culture came to be and how it has shifted since 2023.

## Main themes

### From sceptic to agentic coding

- Armin Ronacher says his view of AI for programming was very negative until February-March 2025. By May he felt “nothing is going to be the same anymore” ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).
- He estimates more than 80% of his startup's code is now written by agents, mostly Claude Code and Codex. He gives them the work he does not want to do, such as reproduction cases and a debugging visualiser, while staying in control of the rest ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).
- He still wants to hire people, because “Claude is not a human” and cannot replace a motivated team. He also compares agentic coding to a slot machine and criticises startups that advertise 996 hours ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).

### Languages and errors when agents write the code

- Ronacher argues language choice matters more with agents, not less. He had an agent write the same program 10 times in several languages and found it did much better in Go than in Python or Rust ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).
- He picked Go for his email-parsing startup for its pragmatism and thin abstractions. He finds Rust too rigid for rapid iteration ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).
- From his Sentry years, he says TypeScript adoption had no measurable effect on JavaScript error rates. He wants runtimes to carry much richer error context, since the interesting errors happen in production, not debug builds ([Ronacher](/podcasts/pragmatic-engineer/2025/10/python-go-rust-typescript-and-ai-with-armin-ronacher/)).

### Vibe coding versus AI-assisted engineering

- Addy Osmani separates the two: vibe coding suits prototypes and learning, while production work needs specs, tests and an engineer who understands what ships. He says you should only commit code you can fully explain to someone else ([Osmani](/podcasts/pragmatic-engineer/2025/10/beyond-vibe-coding-with-addy-osmani/)).
- His 70% problem: LLMs build most of an app quickly but struggle with the last stretch of regressions, maintainability and security. Experienced engineers finish it; juniors tend to keep re-prompting ([Osmani](/podcasts/pragmatic-engineer/2025/10/beyond-vibe-coding-with-addy-osmani/)).
- Osmani cites a study showing human review becomes the bottleneck as AI raises code velocity. He treats an agent's approval as one signal, like a junior's LGTM, and calls AI reviewing AI-written code a slippery slope ([Osmani](/podcasts/pragmatic-engineer/2025/10/beyond-vibe-coding-with-addy-osmani/)).
- He is most excited about asynchronous background agents such as Jules and Codex for tests and migrations, but says finite attention limits how many one person can supervise ([Osmani](/podcasts/pragmatic-engineer/2025/10/beyond-vibe-coding-with-addy-osmani/)).

### Google's engineering culture, then and now

- Gergely Orosz and Elin Nilsson trace Google's custom stack (Borg, Spanner, Piper, Critique and more) to the demands of planet-scale search. Kubernetes came from lessons learned on Borg, which Google still uses internally ([Google](/podcasts/pragmatic-engineer/2025/10/googles-engineering-culture/)).
- Nilsson describes Google as several companies sharing one engineering culture. Mandatory code review, design docs even for small projects, paid and capped on-call, and promotion committees are part of it ([Google](/podcasts/pragmatic-engineer/2025/10/googles-engineering-culture/)).
- Orosz says the 6% layoffs of 2023, after years of near-total job security, changed the mood. Pandemic-era leaks had already reduced internal transparency ([Google](/podcasts/pragmatic-engineer/2025/10/googles-engineering-culture/)).
