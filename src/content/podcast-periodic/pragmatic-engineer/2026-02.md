## Overview

February on The Pragmatic Engineer put AI coding in historical context. Grady Booch, Andrey Breslav and Mitchell Hashimoto each looked back on decades of building software and tools, then described how agents change the work. All three treat AI as a shift in abstraction and workflow rather than the end of the profession.

## Main themes

### AI as the next level of abstraction

- Grady Booch frames software history as three golden ages: algorithmic abstraction from the late 1940s to the late 1970s, objects in the 1980s and 1990s, and systems and platforms from around 2000. AI coding tools are the latest step in the third ([Grady Booch](/podcasts/pragmatic-engineer/2026/02/the-third-golden-age-of-software-engineering-thanks-to-ai-with-grady-b/)).
- Gergely Orosz raises Dario Amodei's claim that software engineering will be automatable in 12 months. Booch rejects it and says Amodei has “a fundamental misunderstanding as to what software engineering is” ([Grady Booch](/podcasts/pragmatic-engineer/2026/02/the-third-golden-age-of-software-engineering-thanks-to-ai-with-grady-b/)).
- Booch expects the delivery pipeline and simple app building to be automated, with job losses where work is messy and complex. His advice to those affected is to move up a level and worry about systems ([Grady Booch](/podcasts/pragmatic-engineer/2026/02/the-third-golden-age-of-software-engineering-thanks-to-ai-with-grady-b/)).

### Language design, from Kotlin to CodeSpeak

- Andrey Breslav says Kotlin borrowed proven ideas from Scala, C#, Groovy and Gosu, under the slogan of a pragmatic language for industry. It took from autumn 2010 to February 2016 to reach 1.0 ([Kotlin](/podcasts/pragmatic-engineer/2026/02/the-programming-language-after-kotlin-with-the-creator-of-kotlin/)).
- Java interoperability took more effort than any other feature. Treating every Java type as nullable failed in practice, so the team designed platform types while keeping null safety free at runtime ([Kotlin](/podcasts/pragmatic-engineer/2026/02/the-programming-language-after-kotlin-with-the-creator-of-kotlin/)).
- Breslav's new language, CodeSpeak, is a programming language based on English that uses an LLM as a library. From anecdotal experience he says it can shrink a lot of code about 10x ([Kotlin](/podcasts/pragmatic-engineer/2026/02/the-programming-language-after-kotlin-with-the-creator-of-kotlin/)).
- He argues that chatting with agents loses intent, because teammates only see the generated code, and expects better testing, review tools and agent-first IDEs ([Kotlin](/podcasts/pragmatic-engineer/2026/02/the-programming-language-after-kotlin-with-the-creator-of-kotlin/)).

### Working alongside coding agents

- Mitchell Hashimoto always wants an agent doing something: “If I'm coding, I want an agent planning. If they're coding, I want to be reviewing.” ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/)).
- He runs at most two agents, sometimes in competition on harder tasks, turns off desktop notifications and starts slow research tasks before leaving the house ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/)).
- Claude Code came up in both the Hashimoto and Breslav episodes. Breslav urges sceptics to learn AI tools and calls cutting junior hiring a mistake ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/), [Kotlin](/podcasts/pragmatic-engineer/2026/02/the-programming-language-after-kotlin-with-the-creator-of-kotlin/)).

### Open source under pressure

- Hashimoto says HashiCorp had no repeatable business for four years. Its first product, Atlas, failed because no single budget owner would buy the whole stack, which led to open core and per-product enterprise sales ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/)).
- His lesson is that companies want to pay for software but fight over whose budget owns it, and corporate buyers do not care about open source ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/)).
- AI has removed the effort barrier in open source. Ghostty now rejects AI-written pull requests without an accepted feature request, and Hashimoto says Git and GitHub do not yet fit agent-driven workflows ([Mitchell Hashimoto](/podcasts/pragmatic-engineer/2026/02/mitchell-hashimotos-new-way-of-writing-code/)).
