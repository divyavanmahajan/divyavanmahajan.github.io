## Overview

August on Practical AI looked at what surrounds the model in a real application: vector databases, orchestration and model middleware. A policy episode weighed the EU AI Act and the White House's Blueprint for an AI Bill of Rights, and TurinTech's CTO showed how LLMs can make code faster.

## Main themes

### Vector databases and retrieval

- Prashanth Rao defines a vector database as one that “efficiently manages, stores, and updates vectors at scale” and sees it as a natural evolution of NoSQL ([Vector databases](/podcasts/practical-ai/2023/08/vector-databases-beyond-the-hype/)).
- Rao warns that adding vectors to Postgres or Elasticsearch can be a square peg in a round hole, and names Milvus, Weaviate and Qdrant as mature options ([Vector databases](/podcasts/practical-ai/2023/08/vector-databases-beyond-the-hype/)).
- His trade-offs include indexing versus query speed, recall versus latency, in-memory versus on-disk indexes and hybrid search. He notes HNSW uses a lot of memory and indexing can take hours or days ([Vector databases](/podcasts/practical-ai/2023/08/vector-databases-beyond-the-hype/)).
- Daniel Whitenack adds that embedding speed and dimension matter when embedding something like 200,000 PDFs ([App stack](/podcasts/practical-ai/2023/08/the-new-ai-app-stack/)).

### The model is not the application

- Using Andreessen Horowitz's emerging LLM app stack diagram, Whitenack calls the idea that the model is the application “basically a falsehood” ([App stack](/podcasts/practical-ai/2023/08/the-new-ai-app-stack/)).
- His mental model has three spokes (app and hosting, data and resources, model and middleware) joined by an orchestration hub, built DIY or with LangChain ([App stack](/podcasts/practical-ai/2023/08/the-new-ai-app-stack/)).
- He coins model middleware for logging, caching and validation, and notes stored prompts and responses can become a dataset for fine-tuning a smaller model ([App stack](/podcasts/practical-ai/2023/08/the-new-ai-app-stack/)).

### Policy trails practice

- Chris Benson calls the Blueprint for an AI Bill of Rights “lovely, fluffy language and not terribly practical AI yet” and says policymakers are far behind practitioners ([AI Bill of Rights](/podcasts/practical-ai/2023/08/blueprint-for-an-ai-bill-of-rights/)).
- GitHub, Hugging Face, Creative Commons and others asked the EU to ease AI Act rules on upstream open-source projects ([AI Bill of Rights](/podcasts/practical-ai/2023/08/blueprint-for-an-ai-bill-of-rights/)).
- Benson questions the right to a human fallback as automation outpaces human oversight. Whitenack expects enterprise compliance frameworks, like SOC 2 or the NIST AI risk framework, to shape practice more than laws ([AI Bill of Rights](/podcasts/practical-ai/2023/08/blueprint-for-an-ai-bill-of-rights/)).

### LLMs that make code faster

- Mike Basios says code optimisation has long been manual work for specialists. TurinTech treats it as translation from slow code to fast code, trading off speed, memory and CPU ([Code optimization](/podcasts/practical-ai/2023/08/automating-code-optimization-with-llms/)).
- He prefers iterative loops to one-shot prompts: compile errors, failing tests and benchmark scores go back to the model. He says this cut an open source library's execution time by 30% ([Code optimization](/podcasts/practical-ai/2023/08/automating-code-optimization-with-llms/)).
- Artemis delivers changes as pull requests that developers still validate. For a client that would not send code to OpenAI, TurinTech deployed Llama 2 on premise ([Code optimization](/podcasts/practical-ai/2023/08/automating-code-optimization-with-llms/)).
