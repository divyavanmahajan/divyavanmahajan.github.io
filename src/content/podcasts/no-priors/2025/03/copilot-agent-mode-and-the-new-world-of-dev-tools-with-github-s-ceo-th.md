## Thesis

Thomas Dohmke tells Sarah Guo and Elad Gil that Copilot is moving from autocomplete to an agent that works on GitHub issues and pull requests, but that humans will still break big ideas into tasks, make architectural choices and review code. He expects a market with many tools and models rather than one winner, and agent pricing based on compute rather than on what a developer costs.

## Key points

- **Agent mode and Project Padawan.** Dohmke describes agent mode in VS Code and a preview where a well-defined issue is assigned to Copilot, which opens a draft pull request and commits changes. A product manager who does not code used it to produce a merged pull request.
- **What agents need.** He lists four criteria for adoption: predictable, steerable, verifiable and tolerable, plus better reasoning models such as the full o3 and progress on SWE-bench.
- **Share of code written.** Early Copilot wrote about 25% of code, which the team first assumed was a telemetry error; it later rose to around 50% depending on language. Copilot had 77,000 organisations and 1.8 million paid users at the last disclosure.
- **Beyond coding.** Dohmke sees code review agents, automatic security fixes and AI-written specs as next, with product, design and engineering roles moving closer together. Legacy COBOL and PHP will keep developers busy for a decade or more.
- **Pricing.** Copilot's $20 per month compares with $21 for GitHub Enterprise. He expects compute-based agent pricing, like a dishwasher that is not priced as a person, and both deflation and higher prices in different parts of software.
- **Open source and learning.** He says open models such as DeepSeek and Flux drive innovation, calls the worry that AI will stop new developers building depth "silly", and connects his optimism to growing up in East Berlin.
