## Thesis

Daniel Whitenack and Chris Benson use the MIT report claiming 95% of generative AI pilots fail to argue that the problem is not model capability but a learning gap. Whitenack says asking "which model should we use?" is the wrong question: business solutions need a set of models plus data integration, built with real software and infrastructure expertise. Benson adds that cutting junior developer hiring while betting on vibe coding is a hidden risk.

## Key points

- **Chat is not a business process.** Whitenack says people assume automating a process works like prompting ChatGPT to summarise an email. His example: a document dropped in a SharePoint folder triggers extraction, a database comparison and an email, which is a custom workflow, not a chat interface.
- **A set of models, not a model.** Even that simple flow needs a document-processing model like Docling, a language model, embedding and rerank models, and safeguard models. Benson compares this to ordinary software architecture.
- **Verticalised tools do better.** Whitenack notes the report found purpose-built vertical AI tools succeeded more often, and argues enterprise AI, like ERP or CRM, will always need customisation.
- **Open models and "Frank's model".** A single model spun up internally with vLLM or Ollama is not an AI platform, he says, which unfairly colours views of open models.
- **OpenAI's signals.** The hosts read GPT-5's flat reception, OpenAI's open-weight reasoning models and its new consulting arm (minimum about $10 million, per Whitenack) as signs the model layer is commoditised and money is in services, as with Accenture, Deloitte and McKinsey.
- **Junior developer risk.** Benson warns that companies not hiring juniors are betting today's seniors plus AI will cover future needs.
