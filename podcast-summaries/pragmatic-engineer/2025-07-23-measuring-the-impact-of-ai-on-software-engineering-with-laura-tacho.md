## Thesis

Laura Tacho, CTO of DX, argues that headlines about AI writing a third of a company's code rest on weak metrics such as accepted suggestions. Drawing on DX data from 180+ companies, she says AI should be treated as a tool to improve developer experience, measured across utilization, impact and cost, with a baseline taken before rollout. Her summary: data beats hype.

## Key points

- **Bad metrics behind the headlines.** Tacho says DX has never seen data supporting claims like 30% of Microsoft's code being AI-written. Acceptance rate shows whether a tool fits its use case, but she calls source code a liability and left acceptance rate out of the DX AI Measurement Framework.
- **Adoption is the lever.** Booking.com reached 65% weekly or daily use through office hours and workshops, against an industry median of 50%. Tacho says many non-users simply lack a licence, or work on novel code where the tools help less.
- **Time savings are not where people expect.** In DX's study, stack trace analysis and refactoring saved more time than mid-loop code generation. Tacho notes engineers code only about 20-25% of their time (an AWS study found 20%), and DORA found some developers less satisfied because AI speeds up the parts they enjoy.
- **Measured results.** WorkHuman saw an 11% gain in developer experience, and its AI users had 15% higher velocity. DX Core 4 data shows more and more complex diffs per engineer, while DORA predicts a 7.2% drop in delivery stability for a 25% rise in AI adoption, which Tacho links to bigger batch sizes.
- **Structured rollouts win.** Tacho says regulated industries such as banking, insurance and pharma get the best results because they roll out deliberately. Indeed ran cohort trials of tools and tested hypotheses such as AI code review for teams across time zones.
- **Practical tips.** For migrations, Tacho suggests doing one file by hand and asking the model to write a prompt that reproduces the diff. She expects companies to replace roadmaps with experiment portfolios.
