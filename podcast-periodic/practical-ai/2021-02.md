## Overview

February on Practical AI dealt with the unglamorous work around models. Gretel argued for engineering privacy into data at the source, Aidoc described fitting AI into hospital workflows without extra effort for staff, and the hosts discussed leaky datasets, code that will not run and low-code tools.

## Main themes

### Privacy-safe data and synthetic records

- John Myers says Gretel launched in fall 2019 to make data anonymisation available to all engineers, not only well-resourced firms ([Gretel](/podcasts/practical-ai/2021/02/cooking-up-synthetic-data-with-gretel/)).
- He explains that redaction leaves re-identification risk, so Gretel generates synthetic records that keep aggregate statistics without a one-to-one match to any source record ([Gretel](/podcasts/practical-ai/2021/02/cooking-up-synthetic-data-with-gretel/)).
- A trained model can produce any number of records, for example 20,000 from 5,000, which helps boost rare classes such as fraud. Myers advises replacing columns like social security numbers first, so the model cannot memorise and replay them ([Gretel](/podcasts/practical-ai/2021/02/cooking-up-synthetic-data-with-gretel/)).
- He calls basic PII detection table stakes and plans containerised services behind a language-agnostic REST API ([Gretel](/podcasts/practical-ai/2021/02/cooking-up-synthetic-data-with-gretel/)).

### AI inside existing workflows

- Elad Walach, CEO of Aidoc, says growing imaging volumes outpace radiologists, so AI should augment them rather than replace them. He calls this a first age of workflow augmentation ([The AI doc](/podcasts/practical-ai/2021/02/the-ai-doc-will-see-you-now/)).
- He describes the product as a safety net that “constantly runs in the background” and reorders the worklist ([The AI doc](/podcasts/practical-ai/2021/02/the-ai-doc-will-see-you-now/)).
- After a clinician demanded zero button clicks, half of Aidoc's engineering went into integration with legacy hospital systems. Walach says deployments went from almost none to hundreds of hospitals for Aidoc alone ([The AI doc](/podcasts/practical-ai/2021/02/the-ai-doc-will-see-you-now/)).

### Failing code, leaky data and low-code tools

- Daniel Whitenack discusses Rajiv Shah's article: rerunning released code does not validate a model. Shah found about 4,500 holdout examples in the Sarcos dataset that also appeared in the training set ([Low code](/podcasts/practical-ai/2021/02/low-code-no-code-accelerated-code-failing-code/)).
- Whitenack blames broken code on missing dependency versions and containerises everything with Docker, pointing to MLCommons' MLCube ([Low code](/podcasts/practical-ai/2021/02/low-code-no-code-accelerated-code-failing-code/)).
- Chris Benson predicts that deep learning will have many low-code and no-code options and “that some of them become quite good” ([Low code](/podcasts/practical-ai/2021/02/low-code-no-code-accelerated-code-failing-code/)).
- Using Lambda Labs benchmarks, Whitenack found two PCIe-connected RTX 3090s beat two NVLink-connected RTX 8000s, so GPU generation can matter more than interconnect ([Low code](/podcasts/practical-ai/2021/02/low-code-no-code-accelerated-code-failing-code/)).
