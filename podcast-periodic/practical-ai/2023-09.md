## Overview

September on Practical AI had two episodes. Demetrios Brinkmann of the MLOps Community argued that most teams reaching for fine-tuning really need retrieval augmented generation, and askui's Dominik Klotz showed how vision models reading screenshots can automate user interfaces on any operating system.

## Main themes

### Fine-tuning versus retrieval

- Brinkmann says fine-tuning fits teaching a model a new function or output format, such as OpenAI's function calling, not your knowledge or voice ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).
- Daniel Whitenack says fine-tuning on raw company documents at best creates “a better autocomplete model to autocomplete your type of documents”, not a better question-answering model ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).
- Brinkmann calls question-answer systems the hello world of LLM work and says RAG with few-shot examples is the right design. He reminds listeners that fine-tuning needs collected, labelled and cleaned data ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).
- He doubts Code Llama can overcome a base model that saw little code ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).

### Keeping LLM systems simple

- Brinkmann dismisses public benchmarks for specific use cases. Whitenack adds that ChatGPT is a product with layers on top, not a model, so it is a poor baseline ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).
- Whitenack often writes LLM chains in plain Python instead of LangChain or LlamaIndex for easier debugging. Brinkmann says many startups with real revenue use no vector database ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).
- The community's LLM survey found 61% of respondents using LLMs at work. Its first course, on RAG, grew from a hackathon where teams built QA bots on the 17,000-member community Slack ([Fine-tuning vs RAG](/podcasts/practical-ai/2023/09/fine-tuning-vs-rag/)).

### Vision models that automate interfaces

- askui takes a screenshot, detects buttons, text fields and icons with an object detection model, and maps natural-language instructions onto them. Klotz says one general model covers Android, Windows and Linux ([Automate all the UIs!](/podcasts/practical-ai/2023/09/automate-all-the-uis/)).
- Natural language lets non-technical users automate interfaces, while a code view is there when low-code hits its limits ([Automate all the UIs!](/podcasts/practical-ai/2023/09/automate-all-the-uis/)).
- Use cases have moved from UI regression testing to robotic process automation. Klotz advises using synthetic data and never production data in tests ([Automate all the UIs!](/podcasts/practical-ai/2023/09/automate-all-the-uis/)).
- Coming from software, Klotz learned ML the hard way and built a Streamlit labelling tool for five chained models. He suggests pairing one researcher with one software or DevOps engineer ([Automate all the UIs!](/podcasts/practical-ai/2023/09/automate-all-the-uis/)).
