## Overview

May on The Pragmatic Engineer was about programming languages and the tools around them. Anders Hejlsberg and Alice Ryhl explained what made TypeScript and Rust succeed, and Dax Raad described how OpenCode grew as an open source coding agent. All three guests asked what AI changes in the craft, and all three said human judgement still matters.

## Main themes

### Languages succeed as whole developer experiences

- Hejlsberg argues a language is never just a compiler: the product is the full edit, compile, run and debug cycle, and languages are a 10-year play ([Hejlsberg](/podcasts/pragmatic-engineer/2026/05/typescript-c-and-turbo-pascal-with-anders-hejlsberg/)).
- TypeScript began when the Outlook.com team asked for Script#. His team proposed an erasable type system instead, and he credits its adoption to the tooling that types enabled and to open development on GitHub ([Hejlsberg](/podcasts/pragmatic-engineer/2026/05/typescript-c-and-turbo-pascal-with-anders-hejlsberg/)).
- He describes a lazy, interactive compiler that must answer within 200 milliseconds, unlike textbook compilers. TypeScript is also being ported to native code ([Hejlsberg](/podcasts/pragmatic-engineer/2026/05/typescript-c-and-turbo-pascal-with-anders-hejlsberg/)).
- C# came out of the Sun versus Microsoft lawsuit and aimed to pair the power of C++ with Visual Basic's ease of use ([Hejlsberg](/podcasts/pragmatic-engineer/2026/05/typescript-c-and-turbo-pascal-with-anders-hejlsberg/)).

### Rust: mistakes become compile errors

- Ryhl says Rust is the first language without a garbage collector whose compiler systematically catches common mistakes, through features such as no null, errors as values and exhaustive match ([Rust](/podcasts/pragmatic-engineer/2026/05/why-rust-is-different-with-alice-ryhl/)).
- She argues memory safety matters because even a very good programmer will eventually err, and governments now call C/C++ memory vulnerabilities unacceptable ([Rust](/podcasts/pragmatic-engineer/2026/05/why-rust-is-different-with-alice-ryhl/)).
- Ryhl reports that “at the Linux kernel maintainer summit we agreed that Rust is no longer experimental in the kernel.” She contrasts Rust's team-based governance with Python and Linux ([Rust](/podcasts/pragmatic-engineer/2026/05/why-rust-is-different-with-alice-ryhl/)).
- For TypeScript developers she pitches Rust as a backend language for reliable servers, not a frontend replacement ([Rust](/podcasts/pragmatic-engineer/2026/05/why-rust-is-different-with-alice-ryhl/)).

### OpenCode, positioning and the Anthropic block

- Raad says OpenCode won by taking the open source spot first, with a harness that was only good enough for about five months. He argues the open source option eventually becomes the default in dev tools ([OpenCode](/podcasts/pragmatic-engineer/2026/05/building-opencode-with-dax-raad/)).
- When Anthropic blocked Claude subscriptions in OpenCode, the outrage boosted OpenCode's numbers and Raad added official OpenAI support the next day. He criticises the abrupt late-night rollout ([OpenCode](/podcasts/pragmatic-engineer/2026/05/building-opencode-with-dax-raad/)).
- The business rests on OpenCode Zen inference and an enterprise control plane for providers, permissions, budgets and rate limits ([OpenCode](/podcasts/pragmatic-engineer/2026/05/building-opencode-with-dax-raad/)).

### What AI changes for engineers

- Raad warns that agents make feature creep cheap: “Just because we can ship 10 times more doesn't mean we have 10 times as many good ideas to ship out there.” ([OpenCode](/podcasts/pragmatic-engineer/2026/05/building-opencode-with-dax-raad/)).
- He says most engineers cash in AI gains as free time, while motivated ones drown in slop PRs and burn out ([OpenCode](/podcasts/pragmatic-engineer/2026/05/building-opencode-with-dax-raad/)).
- Hejlsberg expects developers to oversee agents like project managers and says “the responsibility for a program does not lie with the AI” ([Hejlsberg](/podcasts/pragmatic-engineer/2026/05/typescript-c-and-turbo-pascal-with-anders-hejlsberg/)).
- Ryhl says AI review bots on kernel mailing lists impressed maintainers, but warns that AI can create false understanding ([Rust](/podcasts/pragmatic-engineer/2026/05/why-rust-is-different-with-alice-ryhl/)).
