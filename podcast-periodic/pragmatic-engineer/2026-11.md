## Overview

November on The Pragmatic Engineer kept returning to software factories: agentic systems of code plus operations, with code as their output. Satya Nadella, Harjot Gill and Katelyn Lesse described how verification and review change when code is cheap. Maude Lemaire offered scaling stories from Slack and GitHub and a sceptical view of AI for performance work.

## Main themes

### Software factories: code becomes the output

- Nadella says code has moved from being the input of software work to its output, so specification and intent matter more. He says onboarding gets easier in a factory because everything is documented and can be queried ([Satya Nadella](/podcasts/pragmatic-engineer/2026/11/software-engineering-after-code-becomes-cheap-with-satya-nadella/)).
- Gill says he merged more than 5,000 pull requests in a month by keeping agent fleets busy ([Harjot Gill](/podcasts/pragmatic-engineer/2026/11/software-factories-and-code-reviews-with-harjot-gill/)).
- Gill puts CodeRabbit's token spend at several million dollars a month. After a CI vendor quoted about $13 million a year, the team built its own CI ([Harjot Gill](/podcasts/pragmatic-engineer/2026/11/software-factories-and-code-reviews-with-harjot-gill/)).

### Verification is the hard part

- Nadella says that “In a world where code generation has become cheap, what has become hard is verification” ([Satya Nadella](/podcasts/pragmatic-engineer/2026/11/software-engineering-after-code-becomes-cheap-with-satya-nadella/)).
- He wants every failure turned back into a verified test case, and favours a separate model family as critique ([Satya Nadella](/podcasts/pragmatic-engineer/2026/11/software-engineering-after-code-becomes-cheap-with-satya-nadella/)).
- Gill lists ways agents can check their own work: TLA+ models, Lean theorems, deterministic simulations, emulated cloud APIs and agent-watched rollouts behind feature flags ([Harjot Gill](/podcasts/pragmatic-engineer/2026/11/software-factories-and-code-reviews-with-harjot-gill/)).
- Lesse argues that once work is verifiable, engineers need not read every line of generated code ([Anthropic](/podcasts/pragmatic-engineer/2026/11/how-anthropic-builds-software-in-2026-with-katelyn-lesse/)).

### Human review moves up a level

- Gill says “the human code review is dead, but the human review is not dead.” At CodeRabbit humans review releases rather than PRs, and human taste and judgment are now the bottleneck ([Harjot Gill](/podcasts/pragmatic-engineer/2026/11/software-factories-and-code-reviews-with-harjot-gill/)).
- At Anthropic, Lesse says, a Claude classifier runs on every change and decides whether humans need to look, how many and from which teams. Mechanical changes such as SDK version bumps can merge without a human, and that share is rising ([Anthropic](/podcasts/pragmatic-engineer/2026/11/how-anthropic-builds-software-in-2026-with-katelyn-lesse/)).

### Agents rebuilding Anthropic's platform

- Lesse says “Every token that Claude serves runs through the Messages API.” A small team without Rust experts rewrote it from a single-region Python monolith to Rust in about five or six months, using shadow traffic ([Anthropic](/podcasts/pragmatic-engineer/2026/11/how-anthropic-builds-software-in-2026-with-katelyn-lesse/)).
- She estimates engineers did not closely read about 80% of the agent-opened pull requests in that rewrite ([Anthropic](/podcasts/pragmatic-engineer/2026/11/how-anthropic-builds-software-in-2026-with-katelyn-lesse/)).
- Claude Managed Agents moved from a sandbox per request to durable harness servers, sandboxes on demand and credentials injected at egress, on roughly a third of the CPU ([Anthropic](/podcasts/pragmatic-engineer/2026/11/how-anthropic-builds-software-in-2026-with-katelyn-lesse/)).

### Scaling by understanding real usage

- Lemaire says Active Record hid query costs at GitHub, where pull requests and issues ran on only 16 shards and the repo home page made over 100 MySQL queries ([Maude Lemaire](/podcasts/pragmatic-engineer/2026/11/scaling-slack-and-github-with-maude-lemaire/)).
- At Slack she replaced costly headless Chrome load tests with lightweight Go clients ([Maude Lemaire](/podcasts/pragmatic-engineer/2026/11/scaling-slack-and-github-with-maude-lemaire/)).
- She says AI has barely helped with performance investigations. At Cursor, Opus proposed parallelising tasks only about 1% of users ran ([Maude Lemaire](/podcasts/pragmatic-engineer/2026/11/scaling-slack-and-github-with-maude-lemaire/)).
